Istilah Dasar Dulu

Sebelum masuk ke aturan-aturan, ini konsep yang muncul di HAMPIR SEMUA sumber. Kalau paham ini, sisanya jauh lebih gampang dicerna.

Claude For Dummies

@rubenhassid
Panduan pemula
  • Token = satuan "potongan kata" yang dipakai Claude buat baca & nulis. 1 halaman teks ≈ 500 token. Ini dasar hitungan biaya & batas pemakaian.
  • Context window = "meja kerja" sementara Claude selama 1 percakapan. Makin penuh, makin gampang lupa hal di awal — makanya chat kepanjangan bikin Claude "ngaco". Solusinya: buka chat baru.
  • Sycophancy = sifat Claude dilatih buat nurut & setuju sama kamu. Kalau kamu bilang sesuatu yang salah, dia bisa aja ikut manggut-manggut. Ini akar dari "Claude jangan terus setuju" yang kamu minta.
  • 3 wujud Claude: Chat (ngobrol doang) → Desktop app (bisa baca file komputer) → Cowork (kerja sendiri berjam-jam, bikin dokumen langsung).

Anatomi folder .claude/

@akshay_pachaar
Teknis, disederhanakan
  • Ada 2 folder pengaturan: satu di komputer kamu secara umum (berlaku ke semua proyek), satu lagi di dalam 1 proyek spesifik (cuma berlaku di situ).
  • CLAUDE.md = file aturan utama, dibaca Claude paling pertama tiap mulai sesi kerja.
  • CLAUDE.local.md = aturan personal kamu doang, ga ke-share ke tim/orang lain.
  • Hooks = script yang maksa — beda sama aturan tertulis yang cuma "saran". Dijelasin detail di Bagian G.
  • Aturan tertulis di CLAUDE.md itu cuma disaranin, bukan dipaksa — Claude bisa aja ga ngikutin 100%.
CLAUDE.md
File teks berisi aturan kerja, khusus dibaca sama Claude Code. Taruh di folder utama proyek.
AGENTS.md
Sama fungsinya kayak CLAUDE.md, tapi formatnya "universal" — dibaca Claude, Codex, Cursor, dan AI coding tool lain sekaligus.
Prompt
Pertanyaan/perintah yang kamu ketik ke AI.
Hook
Script otomatis yang jalan sendiri di momen tertentu (misal: sebelum nyimpen file) — AI ga bisa nolak/ngabaikan.
Repo / repository
"Folder proyek" yang disimpan di GitHub, biasanya berisi kode + dokumentasi.
Skill
Paket instruksi siap pakai buat 1 tugas spesifik, dipanggil otomatis atau lewat perintah singkat (misal /negosiasi).
B

Panduan 10 Menit — Charlie Hills (lengkap, poin demi poin)

Ini thread yang kamu minta dijelasin detail. Charlie Hills marketer (bukan developer!) yang belajar Claude Code dari nol selama 173 hari sampai jalanin 100% bisnis kontennya. Ini seluruh isi panduannya, #1 sampai #9.5.

Give me 10 minutes. I'll teach you 80% of Claude Code.

@charliejhills — 23 Aug 2026
Pemula → mahir
1

Nyalain Claude Code (±2 menit)

Langganan Claude Pro ($20/bulan cukup buat mulai). Install lewat 1 command di code.claude.com/docs. Buka lewat terminal atau app desktop (kalau baru pertama kali, mulai dari app desktop, lebih gampang).

Bikin file CLAUDE.md — ini "latar belakang" kamu: siapa kamu, suka apa, mau Claude kerja gimana. Tapi Charlie saranin: jangan langsung nulis dari nol. Lebih baik ngobrol dulu secara natural sama Claude, baru minta dia yang nulisin/update file itu belakangan — soalnya di awal kamu belum tau mana yang penting buat dicatet.

1.5

Buka menu /config

Itu tempat semua pengaturan Claude Code (~40 opsi). Charlie sendiri baru buka ini di hari ke-173 — poinnya: selalu ada hal baru buat dipelajarin, ga usah stres harus tau semua dari awal.

2

Rencana dulu sebelum eksekusi

Ketik /plan (atau tekan shift+tab) — Claude bakal nyusun rencana dulu, nanya apa yang mau kamu ubah, baru mulai kerja. Mode ini read-only (ga ngubah apa-apa dulu) dan jauh lebih murah dibanding harus benerin hasil yang salah arah.

"Plan mode is read-only, and it is far cheaper than rebuilding. A failed build costs more than ten minutes of planning ever will."
2.5

Auto mode

Dulu Claude nanya izin tiap mau ngapa-ngapain (annoying). Sekarang "auto mode" udah jadi default — tetap aman karena tiap aksi tetap dicek sebelum dijalanin, ga asal nurut ke izin yang udah kamu kasih sebelumnya.

3

Install skill/plugin siap pakai (bagian yang kamu tanya)

Charlie nyesel baru sadar ini di bulan pertama — dia sempet bikin ulang tools yang sebenernya udah ada gratis. Ketik perintah buka marketplace (toko skill), lalu install yang relevan. 5 yang dia pakai:

  • Superpowers — buat brainstorming ide (dia sendiri jarang pake).
  • gstack (agent browser) — buka browser asli, baca isi web yang lagi live hari ini (bukan data lama). Bisa masuk ke Gmail/Google Docs/Notion pake login Chrome kamu yang udah ada, tanpa setup koneksi ribet.
  • HyperFrames — nulis kode HTML terus diubah jadi video (mp4). Dia pake buat bikin overlay video YouTube — tinggal deskripsiin overlay-nya, keluar jadi video jadi.
  • Claude HUD — nampilin di pojok layar: lagi ngapain Claude sekarang, dan udah abis berapa (token/biaya) — biar ga kaget tiba-tiba limit abis.
  • Caveman — bikin jawaban Claude singkat banget, ga ada basa-basi pembuka/penutup. Mirip konsep i-have-adhd di Bagian F.

Poin pentingnya: skill yang kamu perlu itu beda-beda tergantung kerjaan kamu — 5 di atas itu buat kebutuhan Charlie (konten/marketing), belum tentu semua relevan buat HR/ATS.

4

Sambungin tools lain (connectors)

Semua koneksi (Gmail, Google Calendar, dll) yang udah kamu setup di claude.ai otomatis kebawa ke Claude Code, ga usah setup ulang. Tinggal aktifin yang beneran kepake tiap hari — biar Claude bisa baca & kerja langsung di app itu, ga perlu copy-paste manual.

5

Isi CLAUDE.md yang bener (baru sekarang, bukan di awal)

CLAUDE.md itu "meja resepsionis", bukan lemari arsip — isinya cuma aturan inti (gaya bicara, format output), bukan tempat numpuk semua koreksi. Kesalahan Charlie di awal: dia nganggep semua koreksi itu berlaku selamanya/global, padahal hampir ga ada yang beneran global.

Ada 2 level: Global (berlaku semua proyek) vs Local (cuma 1 proyek). Pisahin tegas — kalau dicampur, file global-nya jadi "tempat sampah" isinya numpuk ga karuan.

6

Bikin folder per-topik, pelan-pelan

Charlie punya 1 folder per platform media sosial (LinkedIn, YouTube, dst) — tapi dibikin bertahap selama 3 bulan, bukan langsung semua di hari pertama. Baru bikin folder baru kalau topiknya emang udah "sibuk" dan butuh aturan sendiri.

"The restraint is the useful half. Do not open the second folder until the first one is genuinely busy enough to need its own rules."
7

Memory (ingatan otomatis)

Kalau fitur memory belum nyala, ini perbaikan paling gampang. Ketik /memory buat nyalain — Claude bakal otomatis nyatet hal yang dia pelajarin sambil kerja (command yang ketemu, pola yang diperhatiin), lintas sesi, tanpa kamu minta. Kamu tinggal ngarahin, bukan nulis manual semua.

8

Skills — ubah kerjaan berulang jadi 1 perintah pendek

Aturannya sederhana: kalau kamu udah ngetik hal yang sama 2x, jadiin skill. Caranya: ngobrol sama Claude sampe hasilnya pas, terus minta "simpen ini jadi skill". Pilih kata pemicu (trigger word) yang unik — kalau kata pemicunya terlalu umum, dia bisa "nyala" di tengah kerjaan lain yang ga nyambung, malah bikin runyam.

9

Jangan bikin 1 skill isinya banyak hal (skill raksasa)

Kalau 1 skill isinya kepanjangan, Claude ga bakal baca semuanya tiap dipanggil. Charlie punya 214 skill di komputernya, tapi cuma 72 yang pernah beneran kepake — 142 sisanya ga pernah jalan sama sekali. Idealnya: skill itu "spesialis" 1 tugas, bukan "ensiklopedia" isinya macem-macem.

9.5

Bikin hook — biar ga cuma jadi "permintaan"

Aturan tertulis di CLAUDE.md itu cuma permintaan — Claude baca, dipertimbangin, biasanya (tapi ga selalu) dituruti. Hook itu beda: script yang jalan otomatis, Claude ga punya pilihan buat nolak.

Cara ngetesnya: "kalau ini keabaikan sekali aja, aku bakal kesel ga?" — kalau jawabannya "iya", berarti itu seharusnya jadi hook, bukan cuma kalimat di file aturan.

"Rule of thumb: CLAUDE.md guides. A hook forces."
C

12 Aturan yang Sudah Diuji Datanya

Ini paling penting karena ADA ANGKANYA, bukan cuma opini. Andrej Karpathy (peneliti AI terkenal) komplain soal 3 pola kesalahan Claude → 4 aturan dibikin, lalu diuji @Mnilax di 30 project selama 6 minggu, ditambah 8 aturan lagi. Hasil: tingkat kesalahan turun dari 41% jadi 3%.

01 · INTI

Mikir Dulu

Jangan asumsi diem-diem. Kalau ga jelas, harus nanya balik ke kamu, bukan nebak sendiri.

02 · INTI

Simpel Duluan

Solusi paling minim yang nyelesain masalah. Ga usah ditambahin fitur yang ga diminta.

03 · INTI

Ubah yang Perlu Aja

Sentuh cuma bagian yang emang diminta. Jangan sok "beresin" bagian lain sambil lewat.

04 · INTI

Kasih Target, Bukan Langkah

Bilang "harus kayak apa hasil akhirnya", biar Claude sendiri yang cari cara — dan bisa ngecek sendiri udah bener apa belum.

05 · TAMBAHAN

Jangan Suruh AI Nebak yang Harusnya Pasti

Hal yang harusnya "aturan tetap" (misal: kapan harus ulang proses) jangan diserahin ke tebakan AI — bikin aturan jelas di kode/prosesnya.

06 · TAMBAHAN

Batas Waktu/Usaha yang Jelas

Kasih batas biar AI ga muter-muter lama nyoba hal yang sama berulang-ulang tanpa nyadar.

07 · TAMBAHAN

Kalau Ada 2 Pola Beda, Tanya — Jangan Gabung

Kalau nemu 2 cara berbeda buat hal sama, AI harus nanya mana yang dipilih, bukan asal gabungin dua-duanya jadi satu (malah bikin bingung).

08 · TAMBAHAN

Baca Dulu, Baru Bikin Baru

Cek dulu apa udah ada yang serupa sebelum bikin hal baru — biar ga dobel/nubruk sama yang udah ada.

09 · TAMBAHAN

Tes yang Beneran Ngecek, Bukan Formalitas

"Berhasil dites" doang ga cukup — testnya harus beneran ngecek hasil yang BENAR, bukan cuma "ga error".

10 · TAMBAHAN

Ada Titik Aman buat Kerjaan Panjang

Kerjaan multi-langkah butuh "titik simpan" — biar kalau salah di tengah jalan, ga keterusan makin jauh dari jalur bener.

11 · TAMBAHAN

Ikutin Pola yang Udah Ada

Jangan bikin pola/gaya baru sendiri kalau udah ada pola yang biasa dipakai — walau menurut AI polanya "lebih bagus".

12 · TAMBAHAN

Kalau Gagal, Harus Kelihatan

Jangan sampai ada yang "diam-diam di-skip" tapi dilaporin sebagai berhasil. Kesalahan paling mahal itu yang KELIHATAN kayak sukses.

Temuan penting dari eksperimennya: di atas 200 baris aturan, kepatuhan AI anjlok (dari 76% jadi 52% pas dicoba sampe 18 aturan). Kalimat kayak "hati-hati" atau "pikirkan baik-baik" itu nyaris ga ada efeknya (cuma ~30% dipatuhi) karena ga bisa "dites" benar-salahnya — ganti jadi perintah konkret. Saran akhirnya: pilih 6 aturan yang paling relevan sama kesalahan yang beneran kamu alami, jangan asal comot semua 12.

Sistem "Folder Otak Claude" (pola paling sering diulang)

Ruben Hassid nulis pola yang SAMA di banyak thread berbeda — tandanya ini metode yang emang kepake beneran, bukan sekali coba doang. Aku kelompokin per-thread biar jelas beda angle-nya masing-masing.

8 File yang Dipakai "Top 1%"

@rubenhassid
Konsep

  • voice-profile.md — gaya bicara/nulis kamu, dari wawancara 100 pertanyaan ke Claude.
  • anti-ai-writing-style.md — kata/gaya yang DILARANG. Kata dia: 80% isi file ini harusnya soal apa yang DITOLAK.

Setup Cowork dari Nol

@rubenhassid
Panduan awal

  • Cowork = versi Claude Code buat yang bukan developer.
  • Tips: selalu pilih model paling pintar (waktu itu "Opus") + nyalain "Extended Thinking" biar mikir lebih dalam sebelum jawab.

Obsidian buat Ngedit File

@rubenhassid
Alat bantu
  • Obsidian = aplikasi gratis buat buka folder file .md (markdown) supaya tampilannya rapi kayak Google Docs — ga perlu buka Notepad yang penuh tanda pagar (#) & bintang (*).
  • Klik file → langsung ke-render rapi, bisa diedit langsung dari situ.
  • Kenapa ini cocok buat kamu: ga perlu ngerti kode buat ngedit aturan sendiri.

"Anti-Style File" > Larangan Abstrak

@rubenhassid
Insight penting
  • Nyuruh AI "jangan A, jangan B, jangan C" itu lemah — kata dia AI "lupa separuhnya di kalimat ketiga".
  • Yang lebih efektif: kasih file contoh konkret pola/kata yang mau dihindarin, biar AI belajar dari pola nyata.
  • Ini langsung relevan buat rules kamu — instruksi "jangan pakai kata klise" itu abstrak, bisa diperkuat pakai contoh kalimat nyata.

Claude For Dummies (bagian lanjutan)

@rubenhassid
Pemula lengkap
  • 5 aturan ngobrol sama Claude: spesifik, kasih contoh, bilang yang MAU (bukan cuma yang GA MAU), mulai pendek dulu baru ditambahin detail, kalau bingung mulai chat baru.
  • Daftar hal yang Claude bagus (nulis, ringkas dokumen panjang, mikir bareng) vs kurang bagus (info real-time, matematika presisi, bikin gambar).
